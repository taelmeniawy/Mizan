## 2. وحدات الأساس والتحويل

- لكل منتج `base_unit_id` واحدة.
- كل كمية مخزون تُخزَّن كعدد صحيح `qty_micros` بوحدة الأساس × 10^6.
- لكل وحدة شراء/بيع معامل تحويل `factor_num / factor_den` موجب ومختصر.
- تحويل:

```text
base_qty_micros = line_qty_micros × factor_num / factor_den
```

- إذا لم تكن النتيجة عددًا صحيحًا بالمقياس، يُرفض الإدخال.
- الوحدة غير القابلة للتجزئة (قطعة) تتطلب مضاعفات 1,000,000.
- تغيير معامل التحويل لا يغيّر الحركات التاريخية.

**أمثلة:**

| المدخل | المعامل | الناتج |
|---|---|---|
| 2.5 كرتونة | 12/1 | 30 قطعة |
| 3 عبوات | 1/2 | 1.5 كجم |
| 12.5 م | 1/1 | 12.5 م |

## 3. نموذج المخزون — حقائق أصلية + طبقات

### 3.1 الحقائق الأصلية

| الكيان | الحقول الأصلية الثابتة |
|---|---|
| `purchase_lots` | `original_qty_micros`, `original_supplier_cost_piastres`, `original_landed_cost_piastres`, `received_at` |
| `reels` | `original_length_micros`, `supplier_cost_piastres`, `allocated_expense_piastres`, `original_cost_piastres`, `received_at` |

- لا تُعدَّل هذه القيم بعد الترحيل.
- `reels` هي سجل **الهوية الفيزيائية والتتبّع الأصلي** للبكرة (الطول الأصلي، المورد/الفاتورة، والأصل التاريخي).
- `inventory_cost_layers` هي، في **نموذج LCP المقترح**، مصدر **الكمية/التكلفة المتاحة القابلة للاستهلاك**؛ وتشمل `BASE` و`CUSTOMER_RETURN` و`ADJUSTMENT_IN` (الأخير PROPOSED).
- `stock_movements` و`lot_allocations`/`reel_allocations` هي **سجل الأدلة والأحداث والربط**، وليست رصيدًا ثانيًا.
- `lot_inventory_balances`/`reel_inventory_balances` هي **عروض مشتقة** من الطبقات والحركات.
- المتبقي/المباع/التالف/مرتجع المورد **مشتقة** من الحركات والطبقات.
- لا يوجد حقل «رصيد» مستقل قابل للتعديل.

### 3.2 طبقات التكلفة (`inventory_cost_layers`)

| الحقل | الوصف |
|---|---|
| `id` | PK |
| `lot_id` | الدفعة (إلزامي) |
| `reel_id` | البكرة (إلزامي لمنتج REEL، NULL لـLOT) |
| `layer_type` | `BASE` / `CUSTOMER_RETURN` / `ADJUSTMENT_IN` (الأخير PROPOSED) |
| `parent_issue_allocation_id` | للتخصيص الأصلي الذي أنشأ طبقة المرتجع |
| `original_qty_micros` | كمية/طول الطبقة الأصلي |
| `original_cost_piastres` | تكلفة الطبقة الأصلية |
| `position_micros` | الكمية التراكمية الخارجة من الطبقة |
| `remaining_qty_micros` | `original_qty − position` (مشتق/مُتحقَّق) |
| `remaining_cost_piastres` | `original_cost − T_layer(position)` |
| `fifo_anchor_at` | مرجع ترتيب FIFO |
| `fifo_suborder` | كسر تعادل داخل نفس المرجع |
| `status` | OPEN / EXHAUSTED / DAMAGED |
| `created_at` | |

**دالة الطبقة:**

```text
T_L(x) = ROUND_HALF_UP(L0 × x / Q0)
```

حيث `L0=original_cost`، `Q0=original_qty`.

**الاستهلاك:**

```text
outflow_cost = T_L(position + q) − T_L(position)
position += q
```

- `T_L` غير تنازلية؛ `outflow_cost >= 0`.
- استهلاك كامل يعطي `L0` بالضبط.
- التقسيم إلى معاملات متكافئة يعطي المجموع نفسه.
- لا تُطرح تكلفة تاريخية من كمية صافية.

**أنواع الطبقات:**

- `BASE`: طبقة الاستلام الأصلية.
- `CUSTOMER_RETURN`: طبقة ناتجة عن مرتجع بيع قابل للبيع، بتكلفة التخصيص الأصلي.
- `ADJUSTMENT_IN`: طبقة ناتجة عن تسوية بالزيادة؛ **PROPOSED**، وأساس تكلفتها **OPEN** (`OQ-INV-007`).
- لا تُنشأ طبقة `SUPPLIER_RETURN`؛ مرتجع المورد/Tالف يستهلكان الطبقات.
- لا تُنشأ طبقة `DAMAGE`؛ التالف يستهلك طبقة (أو طبقة مرتجع ثم يستهلكها).

### 3.3 أرصدة LOT/REEL — طرق عرض مشتقة

لا تُعتبر `lot_balances`/`reels.remaining_*` حقولًا مستقلة قابلة للتعديل. تُعرَّض **views/Read Models**:

`lot_inventory_balances` / `reel_inventory_balances`:

| الحقل | المعنى |
|---|---|
| `original_qty`, `original_cost` | من الدفعة/البكرة |
| `gross_sale_issue_qty/cost` | مجموع إصدارات البيع |
| `sellable_return_qty/cost` | مجموع طبقات المرتجع القابلة للبيع |
| `net_sold_qty/cost` | `gross_sale − sellable_return` |
| `damaged_qty/cost` | مجموع استهلاك `DAMAGE` |
| `supplier_returned_qty/cost` | مجموع `PURCHASE_RETURN` |
| `adjustment_in/out_qty/cost` | التسويات |
| `remaining_qty/cost` | مجموع الطبقات المتبقية |
| `conservation_diff_qty/cost` | يجب أن يساوي 0 |

- `remaining_*` هو مجموع الطبقات، وليس `original − net_issued` فقط.
- `sellable_return_*` = مجموع طبقات `CUSTOMER_RETURN` فقط؛ `ADJUSTMENT_IN` لا يُحتسب مرتجعًا.
- التالف/مرتجع المورد/التسويات تُخصم منفصلة، وتظهر في المعادلات.

### 3.4 وضع التتبّع

| الوضع | الهوية/التتبّع الأصلي | مصدر الكمية/القيمة المتاحة (LCP PROPOSED) |
|---|---|---|
| `LOT` | `purchase_lots` | طبقات الدفعة (`inventory_cost_layers`) |
| `REEL` | `reels` لكل بكرة | طبقات كل بكرة (`inventory_cost_layers`) |

- `reels` تحمل هوية البكرة والأصل التاريخي، وليست رصيدًا متاحًا ثانيًا.
- لا يمكن تغيير `tracking_mode` بعد وجود حركة.
- لا خلط LOT/REEL لنفس المنتج.
- منتج LOT لا يملك `reels`؛ منتج REEL لا يملك طبقات LOT بدون بكرة.

## 4. FIFO واختيار الطبقات

### 4.1 اختيار الطبقات

1. المنتج + المخزن.
2. الطبقات المتاحة: `remaining_qty > 0`, `status=OPEN`.
3. الترتيب:
   - `fifo_anchor_at` تصاعديًا.
   - ثم `fifo_suborder` (BASE قبل CUSTOMER_RETURN داخل نفس الدفعة، ثم `created_at`/`id`).
   - **ترتيب طبقات المرتجع PROPOSED**؛ البديل بتاريخ الإرجاع (`OQ-INV-013`).
4. تخصيص الأقدم أولًا حتى تغطية الكمية.
5. إذا لم تكفِ، رفض كامل وعرض النقص.
6. التالف/مرتجع المورد/التسويات تستهلك الطبقات بنفس الترتيب، أو طبقة/بكرة محددة إذا اختارها المستخدم.

### 4.2 النموذجان القديمان ولماذا لا يكفيان

#### A — من المتبقي

```text
issue_cost = ROUND_HALF_UP(remaining_cost × issue_qty / remaining_qty)
```

- يعتمد على تقسيم المعاملات.
- 2 م مرة واحدة قد يختلف عن 1+1.
- **مرفوض** كسياسة نهائية.

#### B — صافي تراكمي

```text
T(n) = ROUND_HALF_UP(C0 × n / Q0)
issue_cost = T(n+q) − A
```

- يحفظ الإجمالي عند الاستهلاك الكامل.
- **ينكسر مع مرتجعات تعسفية**؛ المثال التالي.

### 4.3 المثال المضاد الإلزامي: 3 وحدات / 100 قرش

- `Q0=3`, `C0=100`.
- `T(1)=33`, `T(2)=67`, `T(3)=100`.

| الحدث | الحساب | التكلفة | `n` | `A` |
|---|---|---:|---:|---:|
| إصدار 1 | 33 | 33 | 1 | 33 |
| إصدار 1 | 34 | 34 | 2 | 67 |
| إصدار 1 | 33 | 33 | 3 | 100 |
| إرجاع الأول | −33 | −33 | 2 | 67 |
| إرجاع الثالث | −33 | −33 | 1 | 34 |
| إصدار 0.001 | `T(1.001)=33`؛ `33−34` | **−1** | 1.001 | 33 |

- `T(1.001)=ROUND(100×1.001/3)=33`.
- التكلفة السالبة مرفوضة، لكن الكمية متاحة.
- السبب: `A` مجموع تكاليف تاريخية محددة، وليس `T(n)`؛ لا يجوز طرحه من دالة كمية صافية.
- **B لا يُعتمد كما هو.**

### 4.4 الحل: LCP

- كل إصدار يستهلك **موضعًا** داخل طبقة، بتكلفة `T_L(pos+q)-T_L(pos)`.
- المرتجع ينشئ طبقة جديدة بدل تعديل موضع الطبقة الأصلية.
- إعادة الإصدار تستهلك طبقة المرتجع.
- لا `A` عالمي ولا `T(n)` على صافي الكمية.

**مثال 3 وحدات تحت LCP:**

| الحدث | الطبقة | الحساب | التكلفة |
|---|---|---|---:|
| إصدار 1 | BASE | `T(1)=33` | 33 |
| إصدار 1 | BASE | `T(2)−T(1)=34` | 34 |
| إصدار 1 | BASE | `T(3)−T(2)=33` | 33 |
| إرجاع الأول | BASE→RETURN#1 | عكس 33 | 33 |
| إرجاع الثالث | BASE→RETURN#3 | عكس 33 | 33 |
| إصدار 0.001 | RETURN#1 | `T_R(0.001)=0` | **0** |

- 0 غير سالب؛ الباقي 0.999/33 يُستهلك لاحقًا.
- إصدار 1 كامل من RETURN#1 = 33.

### 4.5 المرتجعات الجزئية

لكل تخصيص أصلي:

```text
R(k) = ROUND_HALF_UP(original_alloc_cost × k / original_alloc_qty)
return_cost = R(k_new) − R(k_old)
```

- `k` الكمية المرتجعة التراكمية.
- آخر إرجاع `k=q` يأخذ `original_alloc_cost` بالضبط.
- مثال 2 م/2,333:
  - 1 م مرة: 1,167.
  - 0.5 + 0.5: `R(0.5)=583`، `R(1)=1,167` → 583 + 584 = 1,167.
  - لا 583+583.
- التخصيص الأصلي **صف مرحّل غير قابل للتعديل**. `returned_qty`/`returned_cost` ليست حقولًا تُحدَّث عليه؛ تُشتق من تخصيصات/طبقات المرتجع المرتبطة به، أو تُعرض كـprojection قابلة لإعادة البناء.

### 4.6 إعادة الإصدار والمرتجعات المتعددة

- إعادة الإصدار تستهلك طبقة مرتجع عبر `T_L` الخاص بها.
- يمكن أن يمتد إصدار على عدة طبقات، ولكل طبقة تخصيص منفصل.
- مرتجع من تخصيصات مختلفة: كل مرتجع يشير إلى تخصيصه الأصلي.
- إعادة إرجاع بضاعة أُعيد إصدارها: تُنشأ طبقة مرتجع **فرعية** مرتبطة بتخصيص إعادة الإصدار.
- لا تُعاد كتابة أي تخصيص مرحّل.

### 4.7 الحفظ والتحقق

- `position ≤ original_qty`, `remaining_qty ≥ 0`, `remaining_cost ≥ 0`.
- `outflow_cost ≥ 0`؛ إذا ظهر سالب → رفض/rollback.
- مجموع تكاليف الاستهلاك + المتبقي = تكلفة الطبقة.
- عند `position = original_qty`: المتبقي 0، والتكلفة المستهلكة = الأصلية.
- كل تخصيص/طبقة غير قابلة للتعديل بعد الترحيل.
- عدادات المرتجع على التخصيص الأصلي (`returned_qty`/`returned_cost`) **مشتقة** ولا تُحدَّث على الصف الأصلي.

## 5. البكرات

### 5.1 الأصل والطبقات

- `reels` تحمل الطول/التكلفة الأصليين.
- `inventory_cost_layers` تحمل طبقة BASE للبكرة، وطبقات CUSTOMER_RETURN عند الحاجة.
- `remaining_length/cost` مشتقان من الطبقات.
- لا `lot_balances` للبكرة.

### 5.2 الحالات المقترحة

| الحالة | المعنى | الانتقالات المقترحة |
|---|---|---|
| `SEALED` | مغلقة، لا إخراج | أول قطع → OPENED |
| `OPENED` | مفتوحة وبها متبقٍ | قطع/تلف حتى 0 → EMPTY/DAMAGED |
| `EMPTY` | لا متبقٍ حاليًا | مرتجع العميل يُنشئ بكرة/طبقة مرتجع جديدة ولا يعيد فتح الأصلية (`OQ-INV-012` محسوم)؛ إعادة الفتح لأسباب أخرى تعتمد على `OQ-INV-005` |
| `RETURNED` | أُعيدت للمورد/مصدرها | نهائية/فحص، ما لم تسمح سياسة معتمدة بمرتجع عميل |
| `DAMAGED` | لا كمية قابلة للبيع | تسوية/إعدام، ما لم تسمح سياسة معتمدة بعودة/تسوية |

- الأسماء/الانتقالات **PROPOSED** (`OQ-INV-005`).
- الحالة مشتقة/مُتحقَّقة من الطبقات والحركات، لا مصدرًا مستقلًا.
- إذا أنشأت تسوية معتمدة طبقة متاحة على البكرة نفسها، تُعاد الحالة المشتقة إلى `OPENED`/`OPEN`؛ لا تُمنع الحركة لمجرد أن الحالة السابقة كانت `EMPTY`. مرتجع العميل لا يعيد فتح البكرة الأصلية؛ يُنشئ بكرة مرتجع جديدة (`OQ-INV-012`).

### 5.3 استلام بكرة

1. فاتورة شراء/استلام.
2. إنشاء `purchase_lot` بوضع REEL.
3. إنشاء بكرة/بكرات بأطوال وتكاليف.
4. توزيع تكلفة البند الواصلة على البكرات، مع حفظ فروق القرش.
5. `Σ reel.original_cost = lot.original_landed_cost`.
6. إنشاء طبقة BASE لكل بكرة.
7. لا `lot_balances`.

### 5.4 قطع/بيع جزء

- القطع يستهلك طبقة/طبقات البكرة:
  - `cost = T_layer(pos+c)-T_layer(pos)`.
  - `pos += c`.
- `remaining_length` = مجموع الطبقات المتبقية.
- كل قطع ينشئ `stock_movement` + `reel_allocation`.
- القطع الكامل يفرّغ الطبقة ويجعل الحالة المشتقة EMPTY (إن لم يكن تالفًا/مرتجعًا)؛ ويمكن أن تعود إلى `OPENED` إذا أنشأت تسوية معتمدة طبقة متاحة على البكرة نفسها. مرتجع العميل يُنشئ بكرة جديدة ولا يزيد متبقي الأصلية (`OQ-INV-012`).

**مثال:** 100 م/300,000:
- 37.5 م → 112,500؛ المتبقي 62.5/187,500.
- 10 + 27.5 → 30,000 + 82,500 = 112,500.

### 5.5 تلف/إعدام

- **جزئي:** استهلاك كمية/تكلفة من الطبقات المتاحة، إنشاء `DAMAGE` allocation + حركة، خفض المتبقي، زيادة `damaged_length/cost`.
- **كلي:** استهلاك كل الطبقات المتاحة، `remaining=0`, `status=DAMAGED`، تحويل التكلفة إلى خسارة/تالف.
- البكرة التالفة تبقى قابلة للتتبّع؛ لا تُحذف.
- لا تُستخدم `reel_allocations` للبيع بعد التلف.
- إذا كان التلف جزئيًا وبقي طول صالح، تبقى الحالة OPENED مع `damaged_length` ظاهرًا.

### 5.6 مرتجع بكرة

- يجب تحديد البكرة/الطول.
- نفس البكرة الصالحة: إنشاء طبقة `CUSTOMER_RETURN` مرتبطة بتخصيص القطع الأصلي؛ لا دمج صامت.
- غير معروفة/مختلطة: بكرة/دفعة مرتجع جديدة (`source_type=RETURN`) بتكلفة المرتجع الفعلية؛ لا تُضاف إلى دفعة الشراء الأصلية.
- التكلفة تُعكس من تخصيص الأصل، لا من تكلفة اليوم.
- التفاصيل **PROPOSED** (`OQ-INV-012`).

## 6. التكلفة الواصلة

```text
supplier_cost = سعر بند فاتورة المورد
landed_cost  = supplier_cost + حصة المصروفات المباشرة
```

- يبقى `supplier_invoice_cost` منفصلًا.
- التوزيع حسب `OQ-INV-001`؛ البكرات بالطول/الأساس.
- تحقق: `Σ expense_share = total_expense`، و`Σ reel.cost = lot.landed_cost`.
- المصروفات اللاحقة: `OQ-INV-011`، ولا تغيير تاريخي.

## 7. المرتجعات والتالف ومرتجع المورد

### 7.1 مرتجع بيع قابل للبيع

- يعكس الإيراد التجاري.
- يعكس تكلفة التخصيص الأصلي.
- ينشئ طبقة CUSTOMER_RETURN.
- يعيد الكمية إلى المتاح عبر الطبقة.
- لا يعيد كتابة الفاتورة.

### 7.2 مرتجع بيع تالف

- يعكس الإيراد.
- **تدفق المخزون المقترح:** `SALE_RETURN_IN` ينشئ طبقة `CUSTOMER_RETURN`، ثم `DAMAGE` يستهلكها في **نفس المعاملة**. لا تبقى كمية قابلة للبيع؛ `sellable_return_qty/cost` و`damaged_qty/cost` يزيدان معًا، معادلات Q0/C0 تبقى متوازنة.
- **المعالجة المحاسبية OPEN:** خسارة/تالف مباشرة مقابل COGS، أو عبر مخزون تالف مؤقت ثم إعدام؛ القرار للمالك/المحاسب (`OQ-INV-004`).
- لا يُعتمد «قيد تكلفة فقط بلا حركة كمية» بديلًا إلا إذا أمكن إثبات اكتمال الكمية والتالف وحفظ التكلفة وتسوية الحركات؛ هذا غير مثبت حاليًا.

### 7.3 مرتجع شراء

- يشير إلى فاتورة الشراء والدفعة/البكرة.
- يستهلك الطبقات المتاحة (أو طبقة محددة).
- يخفض الكمية/التكلفة المتاحة، ويزيد `supplier_returned_*`.
- لا يغيّر COGS تاريخية.
- إذا استُهلك جزء من الدفعة: `OQ-PUR-002`.

### 7.4 تالف من المخزون

- يستهلك الطبقات المتاحة.
- يزيد `damaged_*`.
- لا يعود للبيع.
- يمكن تتبع `Damaged Inventory` كأصل مؤقت أو تحميل الخسارة؛ `OQ-INV-004`.

### 7.5 معادلات المطابقة

**الكمية:**

```text
Q0 = remaining_qty
   + net_sold_qty
   + damaged_qty
   + supplier_returned_qty
   + adjustments_out_qty
   − adjustments_in_qty

net_sold_qty = gross_sale_issue_qty − sellable_return_qty
```

**التكلفة:**

```text
C0 = remaining_cost
   + net_cogs_cost
   + damage_cost
   + supplier_return_cost
   + adjustments_out_cost
   − adjustments_in_cost

net_cogs_cost = gross_sale_issue_cost − sellable_return_cost
```

- المرتجع التالف: `sellable_return_*` و`damage_*` يزيدان معًا؛ `net_sold` ينخفض؛ لا ازدواج.
- مرتجع المورد/Tالف لا يغيّران `net_cogs` التاريخية.
- `Q0`/`C0` ثابتان.

## 9. الحركات والتخصيصات

### 9.1 الحركة (`stock_movements`)

- رأس الحدث: النوع، المصدر، التاريخ، المستخدم.
- الأنواع: `RECEIPT`, `SALE_ISSUE`, `SALE_RETURN_IN`, `PURCHASE_RETURN`, `DAMAGE`, `ADJUSTMENT`.
- المرتجع التالف: `SALE_RETURN_IN` (إنشاء طبقة) + `DAMAGE` (استهلاكها) في نفس المعاملة.
- مجموع كميات/تكاليف الحركة = مجموع تخصيصاتها (يُتحقق لكل نوع، بما في ذلك `RECEIPT`).
- `RECEIPT` ينشئ طبقة BASE عبر تخصيص/صف `RECEIPT` مرتبط بـ`created_layer_id`، بكمية/تكلفة الطبقة المنشأة؛ لا استثناء غير موثق.

### 9.2 أدوار التخصيص

| الدور | الاتجاه | المعنى |
|---|---|---|
| `RECEIPT` | IN | إنشاء طبقة BASE عند الاستلام (PROPOSED للتوحيد) |
| `SALE_ISSUE` | OUT | بيع من طبقة |
| `SALE_RETURN` | IN | إنشاء طبقة مرتجع |
| `DAMAGE` | OUT | تلف/إعدام |
| `PURCHASE_RETURN` | OUT | مرتجع مورد |
| `ADJUSTMENT_IN` | IN | تسوية بالزيادة |
| `ADJUSTMENT_OUT` | OUT | تسوية بالنقص |

- `DAMAGE` و`PURCHASE_RETURN` دوران صريحان في `lot_allocations`/`reel_allocations`.
- `RECEIPT`/`SALE_RETURN`/`ADJUSTMENT_IN` تنشئ `created_layer_id`؛ `SALE_RETURN` يرتبط أيضًا بـ`source_issue_allocation_id`.
- لا تخصيص بلا طبقة/حركة/مصدر.

### 9.3 حقول التخصيص

- `id`, `stock_movement_id`, `cost_layer_id`, `lot_id`/`reel_id`.
- `allocation_role`, `direction`, `quantity_micros`, `cost_piastres`.
- `layer_position_start_micros`, `layer_position_end_micros`.
- `sales_line_id`, `sales_return_line_id`, `purchase_return_line_id`.
- `source_issue_allocation_id` (للمرتجع).
- `created_layer_id` (لإنشاء طبقة).
- `created_at`.

### 9.4 الثوابت

- `quantity > 0`, `cost ≥ 0`.
- للأدوار المستهلكة: `position_start < position_end`، والفرق = الكمية، و`cost = T_L(end)-T_L(start)`.
- لأدوار إنشاء الطبقة (`RECEIPT`/`SALE_RETURN`/`ADJUSTMENT_IN`): المواضع NULL، والكمية = كمية الطبقة المنشأة، و`created_layer_id` مطلوب.
- مجموع تخصيصات الحركة = كميتها/تكلفتها.
- لا تعديل/حذف بعد الترحيل.
- `DAMAGE`/`PURCHASE_RETURN` لا يغيّران تخصيص بيع تاريخي.

## 10. المطابقة

| الفحص | المتوقع |
|---|---|
| `Q0` | = `remaining + net_sold + damaged + supplier_returned + adjustments_out − adjustments_in` |
| `C0` | = `remaining_cost + net_cogs + damage_cost + supplier_return_cost + adjustments_out_cost − adjustments_in_cost` |
| `Σ layers.remaining_qty` | = `remaining_qty` |
| `Σ layers.remaining_cost` | = `remaining_cost` |
| `gross_sale_issue` | = مجموع تخصيصات SALE_ISSUE |
| `sellable_return` | = مجموع طبقات CUSTOMER_RETURN |
| `damaged` | = مجموع DAMAGE |
| `supplier_returned` | = مجموع PURCHASE_RETURN |
| رصيد 1200 | = `remaining_cost` (قابل للبيع) |
| منتج REEL | لا طبقات LOT بدون `reel_id` |
| منتج LOT | لا `reels` |
| `position` | ≤ الأصل، ولا سالب |

- أي فرق يمنع الإقفال ويعرض تقريرًا.
- المطابقة تُعاد بناؤها من الحركات/الطبقات، وليست تعديلًا يدويًا.

## 11. أمثلة رقمية

> كل الأرقام توضيحية.

### 11.1 FIFO مع دفعتين

- A: 100 م، 20.00 = 2,000.00.
- B: 100 م، 22.00 = 2,200.00.
- بيع 120 م:
  - 100 من A = 2,000.00.
  - 20 من B = 440.00.
  - التكلفة 2,440.00.
- B المتبقي: 80/1,760.00.

### 11.2 90 م / 105,000

- إصدار 2 م: 2,333.
- 1+1: 1,167 + 1,166 = 2,333.
- 90 م: 105,000 بالضبط.
- B القديم يعطي 2,334 لـ1+1؛ A قد يعطي 2,333/2,334.

### 11.3 3 وحدات / 100

- B: 0.001 بعد إرجاع الأول/الثالث → **−1**.
- LCP: 0 (غير سالب)، والباقي محفوظ.

### 11.4 بكرة

- 100 م/300,000.
- 37.5 → 112,500؛ المتبقي 62.5/187,500.
- 10+27.5 = 30,000+82,500.

### 11.5 تالف

- دفعة 100 م/2,000.
- تلف 10 م:
  - استهلاك 200.00 من الطبقة.
  - `remaining=90/1,800`، `damaged=10/200`.
  - قيد خسارة 200/مخزون 200.

### 11.6 مرتجع مورد

- دفعة 100/2,000.
- إرجاع 10 قبل البيع: 200.00، `remaining=90/1,800`، `supplier_returned=10/200`.
- بعد بيع جزء: `OQ-PUR-002`؛ لا تغيير COGS تاريخية.

### 11.7 مرتجع بيع 2 م

- تخصيص 2 م/2,333.
- 1 م: 1,167.
- 0.5+0.5: 583+584=1,167.
- إعادة إصدار 1 م من طبقة المرتجع: 1,167.
- التاريخ الأصلي ثابت.
