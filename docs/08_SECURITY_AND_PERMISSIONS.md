# الأمن والصلاحيات — Mizan V1

| البند | القيمة |
|---|---|
| الوثيقة | `08_SECURITY_AND_PERMISSIONS.md` |
| الإصدار | 0.2.0 — Batch 1 |
| الحالة | **PROPOSED / NEEDS APPROVAL** |
| المصفوفة | مقترحة؛ لا تمنح أي صلاحية فعلية |
| المصادقة | محلية؛ لا خادم |

> **كل الصلاحيات في هذه الوثيقة PROPOSED.** لا يُمنح Owner/Manager/Cashier أي صلاحية لمجرد ورودها هنا. المالك يعتمد المصفوفة النهائية (`OQ-SEC-001`). المبدأ المؤكد هو **عدم منح الكاشير وصولًا تلقائيًا لتكاليف الشراء أو الأرباح**، وفصل صلاحيات الأسعار/الخصومات/الاعتماد/الترحيل.

## 2. الأدوار المقترحة

| الدور | الوصف | الحالة |
|---|---|---|
| Owner — المالك | تحكم كامل في الإعدادات/المستخدمين/المالية/التقارير | PROPOSED |
| Manager — المدير | تشغيل يومي، اعتماد استثناءات، مشتريات/مبيعات/مخزون | PROPOSED |
| Cashier — الكاشير | بيع/تحصيل/عروض مسودة، بلا تكلفة/ربح | PROPOSED |

- يمكن إضافة أدوار لاحقًا (مثل محاسب/مراجع) بعد اعتماد المالك.
- لا تُمنح صلاحيات إضافية تلقائيًا لأي دور.

### 4.1 ملاحظات المصفوفة

- **Owner** مقترح له كل الصلاحيات، لكن هذا **ليس** قرارًا معتمدًا؛ قد يقرر المالك فصل بعض الصلاحيات.
- **Manager** لا يدير المستخدمين/الأدوار/استعادة النسخ/الحسابات المالية افتراضيًا.
- **Cashier** لا يرى التكلفة/الربح، ولا يعدّل السعر/الفاتورة، ولا يرحّل مرتجعًا، ولا يدير المخزون/المشتريات.
- `◐` تعني أن المنح يحتاج شرطًا/حدًا معتمدًا، وليس منحًا مفتوحًا.
- لا تُمنح صلاحية بالوراثة الضمنية من «المدير» أو «المالك» دون سطر صريح.
- أي صلاحية جديدة تحتاج تعريفًا في الكتالوج واعتمادًا.

## 6. البيانات الحساسة

| البيانات | من يراها | ملاحظات |
|---|---|---|
| تكلفة الشراء/المورد | Owner/Manager فقط | لا تُرسل للكاشير/الطباعة |
| تكلفة FIFO/البكرة | Owner/Manager | قد تظهر في تقارير مخزون |
| الربح/الهامش | Owner/Manager | Cashier لا |
| أسعار الموردين التاريخية | Owner/Manager | |
| رصيد/حد ائتمان العميل | Owner/Manager (الرصيد قد يُرى للكاشير) | |
| سجل التدقيق | Owner/Manager | |
| كلمات المرور/الرموز | لا أحد | hash فقط |
| مستندات PDF | حسب صلاحية المستند | لا تُشارك تلقائيًا |

- لا تُطبع التكلفة/الربح على فاتورة العميل.
- لا تُعرض تكلفة الشراء في شاشة POS.
- تصدير البيانات الحساسة يحتاج صلاحية منفصلة (PROPOSED).

## 8. التدقيق

### 8.1 الأحداث الدنيا

- إنشاء/تعديل/تعطيل مستخدم/دور/صلاحية.
- ترحيل/إلغاء/عكس/مرتجع.
- تعديل سعر/خصم/اعتماد.
- تحويل عرض/تجاوز انتهاء.
- دفعة/تحصيل/مصروف/تحويل/تسوية.
- تعديل مخزون/جرد.
- نسخ/استعادة.
- تغيير إعدادات/شعار.

### 8.2 الحقول

`event_type`, `entity_type`, `entity_id`, `actor_user_id`, `occurred_at`, `before_json`, `after_json`, `reason`, `correlation_id`, `ip/device` (اختياري للجهاز الواحد).

- لا تُسجَّل كلمات المرور/الرموز.
- السجل **append-only** على مستوى الخدمة؛ منع التعديل/الحذف على مستوى DB **PROPOSED**.
- hash chain/تصدير دوري **PROPOSED** (`OQ-SEC-003`).
- مدة الاحتفاظ **OPEN** (`OQ-SEC-003`/`OQ-LEG-001`).

## 9. الفصل بين المهام

| المبدأ | التطبيق المقترح |
|---|---|
| من يعدّل السعر لا يعتمد بالضرورة | Manager يعدّل، Owner/Manager يعتمد حسب الحد |
| من ينشئ العرض لا يصدره بالضرورة | Cashier ينشئ، Manager/Owner يصدر |
| من يرحّل البيع لا يعتمد البيع تحت التكلفة | Owner يعتمد |
| من يدير المستخدمين لا يدير المالية بالضرورة | Owner فقط للاثنين في V1 (مقترح) |
| من ينشئ النسخة لا يستعيدها | Manager backup، Owner restore |
| من يعدّل المخزون لا يعتمد التسوية | Manager ينشئ، Owner/Manager يعتمد |

- في متجر صغير قد يجمع المالك أدوارًا؛ هذا **قرار مالك** لا افتراض.

## 10. تطبيق الصلاحيات

### 10.1 نقاط الفرض

1. تسجيل الدخول/الجلسة.
2. كل Command في Application Service.
3. الاستعلامات الحساسة (تقارير التكلفة/الربح).
4. تصدير/طباعة المستندات.
5. النسخ/الاستعادة.
6. إدارة المستخدمين.

### 10.2 قواعد

- لا تعتمد الواجهة وحدها؛ الخدمة ترفض.
- لا تُستخدم صلاحيات ضمنية (`if owner` في كل مكان)؛ استخدم كتالوجًا.
- سجّل المحاولات المرفوضة الحساسة.
- لا تُمنح صلاحية لجميع المستخدمين افتراضيًا.
