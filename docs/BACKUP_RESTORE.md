# النسخ الاحتياطي والاستعادة — الأساس المحلي

تدعم الخدمة نسخًا محلية على هيئة دليل، ونسخًا مشفرة على هيئة ملف واحد. يمكن إنشاء النوعين واستعادتهما عبر الخدمة البرمجية.

## إنشاء نسخة مشفرة واستعادتها

ينشئ المالك مفتاح استعادة عشوائيًا مرة واحدة ويحفظه على وسيط منفصل تحت سيطرته. افتح ملف المفتاح بوضع الإنشاء الحصري حتى يحتفظ أي مفتاح سابق بمحتواه.

```python
from pathlib import Path
from mizan.backup import BackupService
from mizan.backup_encryption import generate_key
from mizan.db import Database

key_path = Path("E:/mizan-recovery.key")  # مثال لمسار وسيط المفتاح
with key_path.open("xb") as key_file:
    key_file.write(generate_key())
key = key_path.read_bytes()
service = BackupService(Database("data/mizan.db"), "data/documents")
bundle = service.create("backups/manual-001.mizan", actor_id=owner_id, key=key)
service.verify(bundle, key=key)
service.restore(bundle, "recovery/manual-001", actor_id=owner_id,
                reason="اختبار الاستعادة بالمفتاح المحفوظ", key=key)
```

للنسخ اللاحقة اقرأ ملف المفتاح المحفوظ. احتفظ بنسخة ثانية من المفتاح في مكان آمن منفصل وجرّب الاستعادة بها. فقدان جميع نسخ المفتاح يمنع استعادة الملفات المشفرة به. يغطي تشفير AES-256-GCM القاعدة والمستندات وأسماءها وملف البصمات. تتحقق الخدمة من الملف المشفر قبل نشره وتستخدم مساحة مؤقتة محلية للبيانات المفكوكة أثناء الفحص والاستعادة. تحتاج الاستعادة حاليًا إلى قاعدة ميزان مهيأة فيها حساب مخوّل بالاستعادة.

## الاستخدام

```python
from mizan.backup import BackupService
from mizan.db import Database

service = BackupService(Database("data/mizan.db"), "data/documents")
bundle = service.create("backups/manual-001", actor_id=owner_id)
manifest = service.verify(bundle)
restored = service.restore(
    bundle, "recovery/manual-001", actor_id=owner_id,
    reason="اختبار استعادة دوري",
)
```

تُنشأ الوجهة كدليل جديد، ويُرفض أي دليل موجود. تحتوي النسخة على `mizan.db` و`manifest.json` والمستندات المسجلة في `document_exports` والأصول المرتبطة بلقطات المستندات. الملفات المؤقتة والملفات غير المرتبطة ليست جزءًا من النسخة.

تستخدم الخدمة SQLite Online Backup API أثناء التشغيل. تُقرأ مراجع الملفات من قاعدة النسخة نفسها، وتُقارن الملفات المنسوخة بالبصمات والأحجام المسجلة فيها. تعتمد هذه الآلية على عدم تعديل المستندات الرسمية المنشورة؛ غياب ملف مطلوب أو تغيّره يُفشل إنشاء النسخة. تُفحص سلامة SQLite والمفاتيح الخارجية وإصدارات الترحيلات قبل نشر النسخة بنقل دليل مؤقت مجاور إلى الوجهة النهائية.

## الجدولة والاحتفاظ

ينشئ `ScheduledBackups` نسخة يومية جديدة مرة واحدة في اليوم، وينسخها بعد التحقق إلى نسخة شهرية، ثم يطبق سياسة الاحتفاظ. النسخة الشهرية نسخة متحققة من النسخة اليومية، لذلك لا تُؤخذ لقطتان من قاعدة البيانات في التشغيل نفسه.

```python
from datetime import date
from mizan.backup import BackupService
from mizan.backup_policy import RetentionPolicy, ScheduledBackups

service = BackupService(Database("data/mizan.db"), "data/documents")
backups = ScheduledBackups(service, "D:/mizan-backups", RetentionPolicy(daily=30, monthly=12))
result = backups.run(actor_id=owner_id, today=date(2026, 11, 18))
```

- المسارات: `daily/YYYY-MM-DD` و`monthly/YYYY-MM`، وتُضاف اللاحقة `.mizan` عند التشفير. إعادة التشغيل في اليوم نفسه لا تستبدل أي نسخة موجودة.
- `prune` لا يحذف إلا الأقدم الزائد عن الحد، وبعد التحقق من أحدث نسخة في الفئة. إذا تعذر التحقق من أحدث نسخة لا يُحذف شيء. النسخ المشفرة تحتاج المفتاح للتحقق، ولذلك يرفض `prune` العمل دون مفتاح بدل حذف بيانات غير متحققة.
- نسخ `pre-upgrade` (‏`create_pre_upgrade` بالوسم) لا يحذفها الاحتفاظ التلقائي؛ تبقى حتى يحذفها المالك.
- الحدود الافتراضية 30 يومية و12 شهرية ونسخة قبل الترقية وفق ADR-0005 §3.4؛ سياسة التكرار وRPO/RTO النهائية ما زالت `OQ-BKP-003`.
- عند حذف نسخ قديمة يُسجَّل `BACKUP_PRUNED` في سجل التدقيق.

## النسخة خارج الجهاز

`BackupService.copy_to` ينسخ حزمة متحققة إلى وسيط ثانٍ (قرص خارجي أو مجلد مشاركة)، ثم يتحقق من النسخة المنشورة. لا ينسخ قاعدة البيانات الحية، ولا يستخدم مزامنة ثنائية الاتجاه.

```python
service.copy_to(bundle, "E:/mizan-offsite/2026-11-18", actor_id=owner_id)
service.copy_to(bundle, "E:/mizan-offsite/2026-11-18.mizan", actor_id=owner_id, key=key)
```

- تُرفض الوجهة الموجودة أو المتداخلة مع الحزمة المصدر، وتُنشر النسخة بعد التحقق فقط، فلا تبقى وجهة ناقصة عند الانقطاع.
- تُسجَّل النتيجة `BACKUP_COPIED` أو `BACKUP_COPY_FAILED`. تبقى الحزمة المصدر سليمة ويُستخدم manifest الخاص بها.
- توفير الوسيط وتكرار النسخ خارج الجهاز مسؤولية المالك؛ لا يُفترض مزوّد سحابي (`OQ-BKP-001`).

## الاستعادة والتحقق

- يلزم `backup_database` لإنشاء نسخة و`restore_database` للاستعادة، وفق الصلاحيات الموجودة في التطبيق. الاستعادة تتطلب سببًا مسجلًا.
- تُفحص بصمات SHA-256 والأحجام ومراجع المستندات، وتُرفض مسارات الخروج من دليل النسخة.
- النسخة المقبولة تستخدم مخطط الترحيلات الحالي بالضبط. لا تُنفّذ ترقية ضمن الاستعادة تلقائيًا. معنى ذلك أن النسخة المأخوذة بإصدار تطبيق أقدم تُرفض بعد ترقية التطبيق؛ الاستعادة تعمل بإصدار التطبيق نفسه، وسياسة الترقية/الرجوع بين الإصدارات جزء من المرحلة 10 (`OQ-SYS-003`).
- تُنسخ البيانات إلى مرحلة مؤقتة وتُفحص مجددًا قبل ظهور دليل الاستعادة النهائي. فشل النسخ يزيل المرحلة المؤقتة ويحافظ على النسخ السابقة والقاعدة الأصلية.
- الدليل المستعاد يحتوي على قاعدة قابلة للعمل ومجلد `documents`. لا يضم manifest الأصلي لأن العمل اللاحق سيغير القاعدة. تحتفظ حزمة النسخة الأصلية بالـmanifest.
- تُسجل أحداث `BACKUP_CREATED` و`BACKUP_FAILED` و`DATABASE_RESTORED` في قاعدة التطبيق الذي نفذ العملية. فحص `verify` لا يعدّل النسخة.
- فتح النسخة المستعادة وتبديل قاعدة التطبيق إليها خطوة لاحقة؛ الخدمة لا تستبدل قاعدة مفتوحة.

يستخدم الدليل المحلي بصمات لكشف التلف. يتحقق الملف المشفر أيضًا من صحة المحتوى باستخدام مفتاح الاستعادة. تشمل الأعمال المتبقية ربط الجدولة والنسخ بواجهة الخلفية، وتجربة الاستعادة على جهاز منفصل فعليًا، وتثبيت RPO/RTO وتكرار النسخة الخارجية (`OQ-BKP-003`)، وتحديد مدة الاحتفاظ بسجل التدقيق (`OQ-SEC-003`).

## فحص بدء التشغيل

يشغّل `diagnostics.startup_check` فحصًا للقراءة فقط عند بدء التطبيق قبل عرض أي شاشة أعمال، ولا يصلح أو يعيد توليد أي شيء.

```python
from mizan.diagnostics import startup_check

report = startup_check(db, "data/documents")
if not report["ok"]:
    for error in report["errors"]:
        print(error)
```

- القاعدة: `integrity_check` و`foreign_key_check` وحالة المخطط (`current`/`outdated`/`newer`/`unknown`).
- المستندات: وجود كل ملف مسجَّل في `document_exports` ولقطات المستندات، ومطابقة الحجم وSHA-256. المستند المفقود أو المتغيّر يُذكر في التقرير ولا يُعاد إنشاؤه؛ العلاج هو الاستعادة من نسخة متحققة.
- ملفات `.tmp` المتبقية من عرض منقطع تُذكر كتحذير بعدّها، ولا تُحذف تلقائيًا.
- مخطط قاعدة أحدث من التطبيق أو أقدم منه يمنع الفحص الكامل للمستندات ويظهر كخطأ يحتاج ترقية أو إصدارًا مطابقًا.

## سجل التدقيق

- صلاحية `view_audit_log` لمالك المتجر والمدير، والكاشير ممنوع منها (مصفوفة `docs/08`).
- `AuditService.query` يعيد صفحة مرتبة من الأحدث، بمرشحات `event_type` و`entity_type` و`entity_id` و`actor_user_id` ونطاق تاريخ شامل، مع `limit`/`offset`، ويحوّل `before`/`after` إلى كائنات.
- Migration 10 تجعل `audit_events` للإضافة فقط: أي `UPDATE` أو `DELETE` يُرفض على مستوى SQLite. سجل التدقيق لا يُعدَّل من التطبيق.

```python
from mizan.audit import AuditService

page = AuditService(db).query(owner_id, event_type="BACKUP_FAILED",
                             from_date="2026-11-01", through_date="2026-11-30", limit=50)
```

## التشغيل في الخلفية

`mizan.background.BackgroundJob` يشغّل النسخ أو الاستعادة في Thread منفصل، ويستقبل `progress(stage)` و`cancel`، فلا تحتاج الواجهة إلى الانتظار. الإلغاء يرفع `JobCancelled` قبل النشر فلا تبقى حزمة جزئية، والاستثناءات تُحفظ في `state.error` ولا تُرفع داخل الـThread. حالة المهمة: `pending/running/succeeded/failed/cancelled`.

```python
from mizan.background import BackgroundJob

job = BackgroundJob(lambda progress, cancel: service.create(destination, actor_id=owner_id,
                                                           progress=progress)).start()
job.cancel()             # تعاوني: يُلغى قبل النشر
state = job.wait(10)     # running/succeeded/failed/cancelled
```

## التغطية الآلية

`tests/test_phase9_backup.py` (12 اختبارًا) يغطي النسخ مع اتصال WAL مفتوح، واستعادة البيانات والمستندات ثم ترحيل قيد جديد، واستقلال النسخة عن العمليات اللاحقة، وتلف الملفات، والمخطط غير المدعوم، والمفاتيح الخارجية غير السليمة، والصلاحيات، والمسارات غير الآمنة، والأصول التاريخية، واستبعاد الملفات المؤقتة، والتحقق بعد النسخ، وبقاء النسخة السابقة عند الفشل.

`tests/test_phase9_retention.py` (10) يغطي إنشاء اليومي والشهري مرة واحدة، والاحتفاظ بالعدد الأحدث، وعدم حذف نسخ `pre-upgrade`، ورفض الحذف عند تلف أحدث نسخة أو غياب مفتاح النسخ المشفرة، والنسخ الخارجي المتحقق، وانقطاع النسخ الخارجي دون وجهة ناقصة، وإلغاء النسخ عبر callback التقدم، والصلاحيات ومسارات الجذر.

`tests/test_phase9_audit.py` (6) يغطي صلاحيات العرض، والمرشحات والترقيم، وفك `before`/`after`، ورفض `UPDATE`/`DELETE` على `audit_events`، وترقية قاعدة موجودة إلى Migration 10. و`tests/test_phase9_diagnostics.py` (8) يغطي فحص قاعدة سليمة، والمستند المفقود بلا إعادة توليد، وعدم تطابق البصمة، وجذر المستندات المفقود والملفات المؤقتة، والمخطط الأقدم/الأحدث، وقاعدة مفقودة/تالفة، وانتهاك المفاتيح الخارجية. و`tests/test_phase9_background.py` (4) يغطي تشغيل النسخ في Thread منفصل دون حجب المستدعي، وتقارير المراحل، والإلغاء قبل النشر دون حزمة ناقصة، وتسجيل الفشل بلا رفعه من الـThread.

تشمل التغطية الآلية أساس `T-BKP-001..005` والتشفير `T-BKP-006` وتسجيل الفشل في `T-BKP-007`، وعرض سجل التدقيق `T-SEC-008`. اختُبرت الاستعادة بالمفتاح الصحيح ورفض نسخة بمفتاح مفقود أو خاطئ أو بمحتوى تالف أو مبتور. يبقى قبول الاستعادة على جهاز منفصل فعليًا وربط الواجهة أعمالًا يدوية/لاحقة.
