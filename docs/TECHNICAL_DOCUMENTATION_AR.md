# التوثيق الفني والتشغيلي لميزان

يغطي هذا المرجع النسخة المحلية **0.1.0**، ويخاطب المطوّر ومسؤول الدعم. ميزان تطبيق Windows بواجهة Qt عربية وقاعدة SQLite محلية لمتجر واحد ومخزن واحد.

## بنية التطبيق

| المكوّن | دوره |
| --- | --- |
| <bdi>`mizan/app.py`</bdi> و<bdi>`mizan/bootstrap.py`</bdi> | تشغيل تطبيق Qt، وتجهيز مجلد البيانات، وتطبيق الترحيلات، وتهيئة الحسابات والصلاحيات، وفحص بدء التشغيل. |
| <bdi>`mizan/ui/`</bdi> | صفحات PySide6، وتحديد اتجاه الواجهة RTL وتحميل الخط العربي. تعرض القائمة الوظائف المتاحة بحسب صلاحيات المستخدم. |
| <bdi>`mizan/db.py`</bdi> و<bdi>`mizan/migrations.py`</bdi> | الاتصال بـ SQLite مع فرض المفاتيح الخارجية واستخدام WAL. تُسجَّل الترحيلات المطبقة في <bdi>`schema_migrations`</bdi>. |
| <bdi>`mizan/purchasing.py`</bdi> و<bdi>`mizan/sales.py`</bdi> | إدارة المسودات وترحيل مستندات الشراء والبيع والتسويات والمرتجعات. |
| <bdi>`mizan/inventory.py`</bdi> و<bdi>`mizan/lcp.py`</bdi> و<bdi>`mizan/accounting.py`</bdi> | حركات الدفعات والبكرات، وطبقات تكلفة المخزون، والقيود المحاسبية. |
| <bdi>`mizan/quotations.py`</bdi> و<bdi>`mizan/quotation_export.py`</bdi> و<bdi>`mizan/rendering.py`</bdi> | حالة العرض ومراجعته وتحويله، وإصدار PDF الرسمي وطباعته بخط Noto Naskh Arabic المضمّن. |
| <bdi>`mizan/auth.py`</bdi> و<bdi>`mizan/settings.py`</bdi> و<bdi>`mizan/audit.py`</bdi> | الدخول والأدوار والصلاحيات وإعدادات المتجر والفترات وأحداث التدقيق. |
| <bdi>`mizan/backup.py`</bdi> و<bdi>`mizan/backup_policy.py`</bdi> و<bdi>`mizan/diagnostics.py`</bdi> | النسخ والاستعادة والتحقق وسياسة الاحتفاظ وفحص القاعدة والمستندات. |

## قواعد التنفيذ

- تخزَّن مبالغ الفواتير والقيود بأعداد صحيحة بوحدة القرش. تُحفظ الأسعار التي تحتاج دقة أعلى بأجزاء من مليون من الجنيه، وتُخزَّن كمية المخزون بأجزاء صحيحة من وحدة الصنف الأساسية.
- ترحيل المستند يكتب بياناته وحركة المخزون والقيد المتوازن ضمن معاملة واحدة. عند فشل الترحيل ترجع المعاملة إلى حالتها السابقة.
- تتبع الأصناف إما بالدفعة أو بالبكرة. يصرف النظام المخزون وفق ترتيب الدخول في مسار FIFO، وتربط المرتجعات بالكميات الأصلية المصرح بإرجاعها.
- تعتمد الصلاحيات على أدوار المالك والمدير والكاشير. يفحص التطبيق الصلاحيات عند تنفيذ عمليات الأعمال الحساسة، ويعرض أدوات الواجهة حسب الحساب. تُشتق تجزئة كلمة المرور باستخدام PBKDF2-HMAC-SHA256 وملح مستقل.
- يحفظ PDF الرسمي لقطة العرض الصادر. تُسجَّل بيانات الملف وبصمته، وتُراجع سلامته عند فتحه أو التعامل معه في النسخ الاحتياطي.

## المسارات

ترتيب اختيار مجلد البيانات هو خيار <bdi>`--data-dir`</bdi> ثم متغير <bdi>`MIZAN_DATA_DIR`</bdi> ثم مجلد Windows الافتراضي <bdi>`%LOCALAPPDATA%\Mizan`</bdi>.

| العنصر | الوظيفة |
| --- | --- |
| <bdi>`mizan.db`</bdi> | قاعدة البيانات المحلية. |
| <bdi>`documents`</bdi> | ملفات المستندات الرسمية التي يديرها البرنامج. |
| <bdi>`backups`</bdi> | نسخ التطبيق المحلية. |
| <bdi>`logs`</bdi> | المجلد المخصص للسجلات داخل جذر البيانات. |
| <bdi>`%LOCALAPPDATA%\Programs\Mizan`</bdi> | ملفات التطبيق المثبت. يقع هذا المسار خارج جذر بيانات العمل الافتراضي. |

استخدم أمر **نسخة الآن** بدل نسخ ملف قاعدة البيانات الحية مباشرةً. احتفظ بمجلد البيانات بعيدًا عن النسخ التجريبية التي تستخدم <bdi>`--data-dir`</bdi>.

## تشغيل المصدر والاختبارات

نفّذ الأوامر من جذر المستودع باستخدام Python ‏3.12 بنواة 64 بت على Windows. يستخدم المثال مجلد بيانات محليًا للتجربة.

<div dir="ltr">

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m mizan --data-dir .\artifacts\manual-test
.\.venv\Scripts\python.exe -m pytest -q
```

</div>

تشمل الاختبارات منطق الحسابات والمخزون، والتحقق من النسخ، وواجهة Qt، وإنشاء PDF. راجع [استراتيجية الاختبار](09_TEST_AND_ACCEPTANCE_STRATEGY.md) للفصل بين اختبارات البرنامج الآلية واختبارات القبول الفعلي.

## بناء حزمة Windows

المثبّت يُبنى من التطبيق المجمّع بـ PyInstaller ثم NSIS 3. يستخرج أمر البناء رقم الإصدار من <bdi>`pyproject.toml`</bdi> ويحفظ المثبّت وبصمة SHA-256 في <bdi>`artifacts/windows`</bdi>.

<div dir="ltr">

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[windows-build]"
.\.venv\Scripts\python.exe packaging/windows/build.py --makensis 'C:\path\to\makensis.exe'
```

</div>

قبل تحديث بيئة تشغيل، جهّز نسخة متحققة واحتفظ بالمثبّت السابق، ثم أغلق ميزان وشغّل المثبّت الجديد. يمكن بناء مثبّت بهوية اختبار منفصلة عن طريق <bdi>`--test-install`</bdi>. خطوات اختبار الحزمة متاحة في [ملاحظات التغليف](PACKAGING_NOTES.md).

## النسخ والتحقق والاستعادة

- تستخدم خدمة النسخ ميزة SQLite Online Backup. تضم الحزمة القاعدة والمستندات المسجلة، وتفحص البصمات والأحجام والمفاتيح الخارجية ومخطط الترحيلات. التشفير الاختياري يستخدم AES-256-GCM بمفتاح استعادة خارجي.
- تنشئ خدمة النسخ الدورية نسخة يومية ونسخة شهرية من النسخة اليومية المتحققة. الاحتفاظ الافتراضي ٣٠ نسخة يومية و١٢ شهرية. تبقى نسخ ما قبل الترقية خارج الحذف الدوري.
- الاستعادة متاحة للمالك من قاعدة مهيأة تحتوي على حساب مخوّل، وتتطلب سببًا مسجلًا. يشترط التطابق بين مخطط الحزمة ومخطط إصدار التطبيق. تظهر النتيجة في مجلد جديد بعد التحقق، ويظل التطبيق المفتوح متصلًا بمجلده الأصلي.
- لفحص مستند مفقود أو قاعدة تالفة، ابدأ من صفحة **سلامة البيانات** وخذ تفاصيل الخطأ. فحص السلامة يقدّم تقريرًا للقراءة فقط. مرجع الخدمة ومسار العمل موجودان في [توثيق النسخ والاستعادة](BACKUP_RESTORE.md).

## تشغيل نسخة مستعادة أو مجلد تجريبي

أغلق جلسة ميزان الحالية. المثال يشغّل التطبيق المثبّت مع **مسار مجلد الاستعادة** الذي يحتوي على <bdi>`mizan.db`</bdi> و<bdi>`documents`</bdi>. استبدل المسار التوضيحي بالمسار الناتج من الاستعادة.

<div dir="ltr">

```powershell
& "$env:LOCALAPPDATA\Programs\Mizan\Mizan.exe" --data-dir "D:\MizanRecovery\restored-example"
```

</div>

تحقق من مسار البيانات في شريط الحالة ومن سلامة البيانات وبعض الأرصدة المعروفة قبل اعتماد نتيجة الاستعادة للعمل. إذا أردت العودة للمجلد الافتراضي، أغلق البرنامج وافتحه من اختصاره المعتاد، مع مراعاة أن متغير <bdi>`MIZAN_DATA_DIR`</bdi> يغيّر المسار الافتراضي.

## حدود القبول الحالية

| بند | الحالة |
| --- | --- |
| حزمة Windows | أُنجز التثبيت والتشغيل وإعادة التثبيت والإزالة تجريبيًا. البيئة المستخدمة رفضت تسجيل الحزمة في قائمة التطبيقات، فاختُبر مسار التشغيل والإزالة من مجلد البرنامج. |
| التوقيع | المثبّت المحلي غير موقّع، وقبول الحزمة على Windows نظيف ما زال مطلوبًا. |
| الطابعة والاستعادة | إنشاء PDF واختباراته البرمجية مغطّاة. الطباعة الورقية على A4 والاستعادة على جهاز فعلي منفصل ما زالتا ضمن القبول. |
| التوافق بين الإصدارات | الاستعادة تتحقق من مخطط الحزمة. تبقى سياسة ترقية النسخ القديمة والرجوع بين الإصدارات ضمن الأسئلة المفتوحة. |
